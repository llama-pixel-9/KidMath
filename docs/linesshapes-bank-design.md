## The property-table discipline

All table-checkable claims answer from `SHAPE_TABLE`, which mirrors the
mode's own SHAPES table (same keys the ShapeFigure widget draws) —
`authorLinesShapes.js` re-derives every `display.shapeC` claim from it, so
a drawn figure and its stated properties cannot drift. Figure caveats
respected: the drawn rhombus/octagon are never asked for symmetry off the
picture (word questions about ideal shapes are used instead). NAMED_ONLY
polygons (heptagon…dodecagon) carry regular-polygon properties.

## Payloads (mirror the generator)

- count figure: `answerType:"shapeFigure"` + `display {shape, shapeMode:
  "count", rotate}` — numbered prompts ("Shape 4: …") because the same
  question about different drawn shapes reads identically.
- select figure: `display {shapeMode:"select", options:[{shape, rotate,
  value}×4]}`, answer = option INDEX; option data is fixed (reproducible),
  numbered "Round N:" prompts; the verifier proves exactly one option
  satisfies the predicate. Rhombus/parallelogram never appear as select
  targets (a square IS a rhombus).

## Verification

Table claims: sides/vertices/symmetry (by name and by drawn key),
rightAngles/parallelPairs, diagonals (n(n−3)/2), endpoints (segment 2 /
ray 1 / line 0), judged saids for each, moreSides/moreSym/fewestSym
(ties rejected), select predicates. Sums ride countMath. Authored truths
(fold/mirror/riddle/hierarchy/model items) keep judged-consistency and
choice-sanity checks.
